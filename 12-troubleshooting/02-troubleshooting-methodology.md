# روش‌شناسی عیب‌یابی — Troubleshooting Methodology

## 🎯 اهداف یادگیری

در پایان این درس، دانشجو می‌تواند:

- روش ۷ مرحله‌ای عیب‌یابی را توضیح دهد
- مشکل را از لایه پایین به بالا بررسی کند

---

## ۱. روش ۷ مرحله‌ای

| مرحله | توضیح |
|---|---|
| ۱. تعریف مشکل | دقیقاً چه اتفاقی افتاده؟ |
| ۲. جمع‌آوری اطلاعات | چه زمانی؟ چه کسی؟ چه تغییری؟ |
| ۳. تحلیل احتمالات | چه چیزی می‌تواند باشد؟ |
| ۴. ایجاد طرح | چه آزمایشی انجام بدهیم؟ |
| ۵. اجرا | طرح را اجرا کن |
| ۶. ارزیابی | آیا مشکل حل شد؟ |
| ۷. مستندسازی | آنچه یاد گرفتی را ثبت کن |

---

## ۲. عیب‌یابی از پایین به بالا (Bottom-Up)

```
لایه ۱ - فیزیکی: آیا کابل وصل است؟ LED چراغ Switch روشن است؟
    ↓
لایه ۲ - پیوند داده: آدرس MAC درست است؟ Switch کار می‌کند؟
    ↓
لایه ۳ - شبکه: آدرس IP درست است؟ Gateway وجود دارد؟
    ↓
لایه ۴ - انتقال: پورت باز است؟ TCP/UDP کار می‌کند؟
    ↓
لایه ۷ - برنامه: نرم‌افزار تنظیمات درستی دارد؟
```

---

## ۳. سوالات رایج عیب‌یابی

- آیا کابل وصل است؟
- آیا آدرس IP اختصاص یافته؟
- آیا DNS کار می‌کند؟
- آیا Gateway قابل دسترسی است؟
- آیا فایروال ترافیک را مسدود نمی‌کند؟

---

## ❓ سوالات مرور

1. مراحل ۷ گانه عیب‌یابی چیست؟
2. چرا عیب‌یابی از لایه پایین شروع می‌شود؟
3. اگر ping به Gateway کار نکند، مشکل کجا است؟
